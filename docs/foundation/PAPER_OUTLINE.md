# Paper outline (working draft, no results)

Working title: *When does a tuned 4B model beat a cheap API with retrieval? Equal-pool accuracy and cost on BANKING77 and BillSum.* Sections marked **[needs experiment]** cannot be written until the runs exist; nothing below states a result. Allowed and forbidden claims: `RESEARCH_FOUNDATION.md` section 2.

1. **Introduction.** Practitioner question: N labelled examples, train a small model or call an API? Prior crossover work (Pecher 2025; Spiegelhalter 2026; Bertsch 2025) and what it leaves open. Contributions (conjunction, no "first"): equal-pool comparison against retrieval-augmented commercial APIs and kNN; BillSum label-budget curve; break-even with tuning charged; stated tuning effort per arm; honest reporting of where fine-tuning does not win.
2. **Related work.** Fine-tuning vs ICL by sample size; retrieval ICL; cost/break-even analyses; summarisation evaluation validity. Table of close papers with data, models, methods, N, metric, cost (from `agents/01-literature.md` section 2).
3. **Study design.** Tasks and data (licences, leakage; `DATASET_AUDIT.md`); arms and information equivalence; pools, N levels, replicates; tuning protocol (4 trials per system); API protocol (stochastic/reasoning labels); test isolation and pre-registration; gated pilot as a reported prerequisite.
4. **Evaluation and statistics.** Metrics; conditional estimand; crossed mixed model; Holm family of six contrasts; inconclusive-outcome rule; MDGs per cell; cost model, Q\* with Fieller intervals, labelling axis.
5. **Results.** 5.1 BANKING77 accuracy vs N, all arms incl. kNN **[needs experiment]**. 5.2 Confirmatory contrasts table (six rows: delta, Holm p, CI, outcome) **[needs experiment]**. 5.3 BillSum ROUGE-L/BERTScore vs N, stratified by near-duplicate bin and length **[needs experiment]**. 5.4 Human faithfulness validation, 60 bills, if H2 resolves **[needs experiment]**. 5.5 Cost per correct and break-even with sensitivity grids **[needs experiment, measured tokens and times]**. 5.6 Exploratory: LEDGAR, random-vs-stratified at N=200, technique ablation, constrained decoding, head-based bridge **[needs experiment]**.
6. **Discussion.** Bracketed crossover; when kNN or the API suffices; what drives the choice (data, volume, utilisation); comparison to Spiegelhalter/Bertsch numbers (qualitative only, different protocols).
7. **Limitations.** One classification benchmark and one summarisation benchmark; two models, three APIs, one GPU type and imputed GPU price; conditional-on-training-set estimand; N=200 underpowered by design; public-benchmark contamination; prompts not tuned; generated-label protocol vs classification head; API nondeterminism; ROUGE-only summarisation if no human study; tuning bar versus prior work.
8. **Ethics, licences, release.** Datasets and terms (BillSum statutory basis, LEDGAR ids only, SAMSum excluded, paid API tiers, no training on API outputs); adapters for BANKING77 and BillSum; API predictions with no-training notice; compute and cost disclosure.
9. **Reproducibility appendix.** Pre-registration tag, `frozen_arms.json` hash, test-read ledger, pinned versions, per-prediction and per-run schemas, price and terms dates.
Appendices: power simulation and MDG tables; full per-cell results; prompt texts; negative results of the pilot stage (G1-G7 outcomes).

Venue path (L-11): preprint, workshop paper after about eight weeks, then TMLR or an applied journal with the extended paper.
